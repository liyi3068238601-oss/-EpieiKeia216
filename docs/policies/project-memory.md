# 工程事实与项目记忆

项目记忆用于恢复非显然经验并定位证据。它是待核验线索，不能替代当前源码、测试结果、已接受决策或任务账本。

## 事实来源

- **当前实现：** 对“代码现在做什么”，核对当前 checkout 的源码与 commit；需要运行时结论时，记录真实 API/程序输出、命令、工作目录和退出码。
- **行为契约：** 对“系统应当做什么”，查看同一 revision 的测试，并实际运行相关测试。测试文件表达预期；只有运行结果才能证明被测用例通过。
- **设计决策：** 使用已合并且有独立接受记录的 ADR。通过权威 status/acceptance ledger 和被接受工件的 hash 确认状态；文档中的旧状态文字不能替代接受记录。
- **阶段与单元状态：** 以 `evidence/P03/status.json` 及它引用的精确 review/acceptance 工件为准。这是 P03 协调账本，不代表产品业务 TaskLedger 已实现，也不替代被接受工件本身。
- **业务任务 owner 与进度：** 只采用可核验的 TaskLedger 实体及其证据。没有实体或证据时标为 unknown；不得从阶段状态、author/reviewer、记忆、提交作者、AGENTS 或交接说明推断。
- **项目记忆：** 经验记录一律是 `experience-lead`。U04 reader 固定赋予这个级别；topic frontmatter 不能提升权限或事实权威。核对源码、测试和已接受 ADR 后才能用于当前决定；保留有价值的旧经验时，标清适用范围、来源和核验时间。

这些来源回答的问题不同：源码描述已实现行为，测试描述预期契约，已接受 ADR 描述获准的设计决定。出现矛盾时先分类所讨论的事实，再检查对应 revision、实际 API 和测试结果；分别记录实现行为、测试预期和决策意图，不让旧记忆覆盖新证据。

## 记忆与项目指令的边界

项目记忆只记录对后续工作有帮助的非显然经验和证据指针，不登记实时 owner、进度、阶段状态或接受状态。每条经验应给出可回查的 repo-relative 路径与 source hash；适用时记录 project_id、base commit 和 reader sampled_at。未实际执行核验时，核验时间和命令证据保持 null；填写了时间或命令不等于模型判断正确。

`AGENTS.md` 只保存稳定、可执行的项目规则和约束。不要把个人传记、人生史或与项目无关的用户画像放入项目指令或项目记忆。

更新经验时保留旧来源的历史意义，并指向当前核验结果；不要把“曾经如此”写成“现在如此”。本政策约束证据整理，不实现通用事实引擎，也不证明模型会在冲突时作出正确判断。
