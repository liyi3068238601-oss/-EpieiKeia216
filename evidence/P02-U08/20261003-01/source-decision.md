# U08 source and implementation decision

Prerequisite U07 is accepted at coordinator baseline 6198ddcf963c7ee594b983f3b1c1fe33f692fb15. Reuse the accepted U05 EventStore and its unchanged migrations/001-event-store.ts. The task card points to SQLite's supported online-backup API. Rechecked primary references: https://www.sqlite.org/backup.html ; https://www.sqlite.org/wal.html ; https://nodejs.org/download/release/v24.14.0/docs/api/sqlite.html#sqlitebackupsourceDb-path-options . Existing pinned Node source research also examined v24.14.0 src/node_sqlite.cc to understand progress callback rejection/finalization. These references motivate the implementation; they are not product test evidence.

Use the existing Node SQLite backup API, not a main-file filesystem copy. Existing backup targets are replaced by that API, so it must target a newly owned private file and publish only after validation via same-volume no-clobber linking. Reuse the existing fixed v1 DDL; support empty v0 initialization to v1 and populated v1 snapshot-only maintenance. No business requirement justifies an artificial v2 or a second migration-version ledger. No third-party code is copied, no dependencies installed and no excluded assets used.

Lifecycle belongs to the trusted coordinator: pause producers, drain accepted writes, reconcile unknown writer receipts while the old connection remains open, close the store, then perform maintenance with producers paused. The private U05 database handle stays private. Preflight schema/version read-only, then BEGIN IMMEDIATE and recheck under the writer lock. Use a second read-only connection as backup source; backup from the locked coordinator connection is not the intended path. Await the backup promise to settle before closing that source. A progress deadline is cooperative between backup steps and is not an absolute wall-clock or filesystem-stall bound. Default deadline is 30 seconds, accepted range 1..30000ms.

Only after actual staged integrity/schema/fact/observation/receipt/material validation and no-clobber publication may empty v0 execute the fixed DDL and set user_version in the same transaction. Do not change journal_mode inside BEGIN. For v1, no DDL or version change. Restore only into a newly created data root using SQLite backup and repeated validation. Never overwrite an existing data root or backup. A failed or uncertain commit requires read-only state inspection, not blind migration replay. After a lost COMMIT acknowledgement, distinguish fully verified v1, fully verified empty v0 and unavailable readback; unavailable is UNRESOLVED_TRANSACTION. A connection-close failure cannot produce a success report. Failed owned snapshots and command evidence stay available for diagnosis; only successfully settled owned staging is cleaned after physical containment checks.

Read-only SQLite can create or use WAL/SHM machinery; do not claim that all ancillary bytes are untouched. Future-version refusal must precede writable source SQL, WAL configuration, backup output or DDL, with actual measured main/WAL state recorded by tests. Controlled SQLite FULL and process kill are separate from physical disk exhaustion or power loss. Those physical conditions, installed ZCode, production data, paid models and installer/portable behavior remain outside this unit.

Mapped scope: packages/storage/backup/; unchanged static migrations/ input; tsconfig.json adds the backup source glob; tools/run-tests.mjs adds the unit selector and all-unit inventory; evidence/P02-U08/20261003-01/. Test mapping: packages/storage/backup/test/backup.test.mjs plus any owned child fixture in that test directory. This is an implementation decision, not an acceptance or assertion that tests have already run.
