# P03-U04 result

Author status: `ready_for_review`; independent review and coordinator acceptance pending. Baseline: `4c5cbda3395cb2e89065fabec75d1d4437e079fe`. Attempt: `20261008-01`.

The implementation adds a bounded synchronous project-memory reader with immutable reader-branded snapshots, exact workspace/project re-resolution, fatal UTF-8 decoding, bounded YAML frontmatter parsing and Marked link tokenization. It selects only topics authorized by the index body, rechecks selected bytes and mapping at capture/read boundaries, and returns explicit `present`, `absent`, `unreadable` or `corrupt` states. Topic packet values carry `project_id`, one capture-wide `sampled_at`, `source_hash` and `experience-lead` authority. Host packet composition fails closed above the 12,000-byte UTF-8 upper bound; no content is truncated. The actual Host ran with synthetic Git and memory fixtures; the installed Hook source executed in a child process under the fixed P01 Node executable. Native app/provider and model were fake, and the Read bridge used a synthetic FileSystem delegate; the existing nonce and receipt gates were exercised.

The implementation includes a narrow Native `Read` stat/range bridge because the pinned Native reader may satisfy a later read from its session cache when mtime and size match. With `projectMemory` and `projectMemoryReadPort` enabled, Host wraps the Native FileSystemPort before `createNativeApp`, binds reads to the live receipt and rejects snapshots whose `project_id` differs from the bound project. Unit-02 verifies this wiring through a synthetic Native factory and FileSystem delegate, including missing-binding and cross-project rejection. The first passing unit-01 run tested the bridge directly and did not prove this wiring; its original result is retained as preliminary history. U04 did not execute the Native core's actual `Read` tool; that integration remains `NOT_RUN` for U09.

Marked `16.4.2` (MIT) and YAML `2.9.0` (ISC) are exact direct dependencies with lockfile integrity and retained license files recorded in `source-adoption.json`. The adopted parser APIs follow the accepted U02 probe; its eight API assertions are source-selection evidence, not U04 behavior coverage. Two dependency setup failures are retained: the first frozen install rejected the stale lockfile, and the next coordinator failed while looking for a better-sqlite3 binary at the wrong path after pnpm itself exited successfully. A fresh isolated frozen-lockfile install succeeded and its SQLite smoke check exited 0.

The final TypeScript build (`build-04-command.json`) and formal `unit-02-command.json` both exited 0. Unit-02 includes the reader cases, Host injection/receipt cases, automatic Native FileSystemPort wiring, project identity rejection, and existing selectors; the captured stdout retains separate 43/43 and 21/21 pass summary blocks. Unit-01 remains separately recorded with its preliminary 43/43 and 19/19 summaries. The contract command exited 0 with two existing P01-U06 checks and is not a U04 integration test. The pinned Native `text-range-reader.ts` source hash and direct dependency/license hashes are recorded in `source-adoption.json`.

The reader is bounded but does not claim a filesystem-wide atomic snapshot against all concurrent writers. U04 does not implement general filesystem write sandboxing; that remains U07 scope.
