# Xiadie V2 项目计划书
## 从复用验证到 1.0.0 正式版

**文档版本：1.1（重建修订版）｜日期：2026-09-30｜配套：计划执行书与独立任务卡**

本书规定目标、分层、来源取舍、版本范围、风险和验收。产品版本从0.0.0到1.0.0；文档1.1不是产品1.1。上轮生成文件没有在本轮环境挂载，本包依据本对话保留方案重新编制，**不是旧ZIP的逐字恢复**。所有实施单元仍为not_started，不代表已经运行产品PoC、构建Windows软件或获得资源再分发许可。

## 1. 项目目标与范围

遐蝶是Windows优先的固定角色AI伴侣应用。她通过可迁移的角色资产、有限Life Memory和受控上下文保持连续表达；通过ZCode主运行时工作；由ZCode在需要时委托DSH完成工作包，DSH可以拥有自己的子代理团队。用户看到一个主交互入口，并能检查任务、工具证据、权限、数据和后台费用。

最终范围保留单主窗口、固定Live2D桌宠入口、托盘、会话与消息管理、多模型配置、两类记忆、Dream、工作及团队协作、个人待办、文件知识、语音、受控外部消息、备份/删除/安装/维护。这些外围体验后置，不进入最小概念验证。旧Python/FastAPI、Mastra等技术选型不作为本次必需依赖；旧最终产品体验仍作为需求参考。[U01][U02]

“最终版”是**本次冻结范围的1.0.0**，不是永不更新。后续新需求另立1.x计划。手机端、多人云租户、任意角色市场、无限自治、自动群发、模型训练、游戏挂机、万能安全沙箱和全自动高质量角色建模不在本范围。跨模型支持以实际矩阵为准，不承诺任意模型具有完全相同人格表现。

### 1.1 不变的边界

| 边界 | 必须落实 | 禁止混淆 |
|---|---|---|
| Core与工作分开 | Core定义角色、记忆语义和上下文；不路由DSH | 不再写Core级 `comfyui→DSH` 映射 |
| 主运行时唯一 | ZCode负责主会话、任务编排与最终工作结论 | 不让ZCode、DSH和新Core互当项目经理 |
| DSH是外部团队 | 可承担完整code/work、派自己的代理 | 不是只允许几个小工具，也不是平级接管用户 |
| 唯一Owner | task_id、attempt、租约版本、写范围和集成者 | 不能两边各自发现需求后重复施工 |
| 两类记忆 | Life有限并可归档，Project按工程事实更新 | 不把90天半衰期用于项目笔记 |
| 事实与叙述分开 | 来源、用户决定、助手建议、解释分类型 | 不把角色示例或未执行计划存成真实历史 |
| 后台可退出 | 有材料、有授权、有资源才运行 | 不要求应用整夜常驻，不虚构离线活动 |
| 复用优先 | 先查现成、再隔离试验、最后补最小缺口 | 不把三个仓库复制后重新造Harness |

资源、模型凭据、渠道资格不足时，任务标blocked_external。能先完成代码和mock测试，但不能把缺少真实验收的Must能力写成正式支持。范围修改需明确决议，不由Agent为了赶进度删掉困难项。

### 2.1 已确认、不能忽略的实现限制

ZCode的子代理持久记忆可配置user/project/local scope。尤其 `persistent-memory.ts` 会在相关条件下给启用memory的profile补入Write/Edit。**审查者标“只读”或手工删掉工具列表不自动成为只读权限保证。** 必须核查最终生效工具及执行端路径权限，必要时关闭该profile自动记忆或给其独立受限笔记目录。[Z04]

DSH公开SDK协议只有三个客户端请求：initialize、session/prompt、shutdown。messageId是入队回执；idle不是业务成功。该固定版本没有单session cancel/close，也没有实际启用的完整审批回传。因此初版使用专属工作包进程，动态扩大权限退回主端处理；恢复只有经过PoC才可称native resume。[D02]

ZCode原生Memory提示包含user/feedback/project/reference，并不意味着天然只有项目技术事实。跨项目用户Life内容不得自动复制进去。原生目录可能在运行时数据根，项目repo仍在不等于原生Memory随目录搬走。[Z03][Z06]

Herta相关机制是Episode、Dream gate、有限live叙述、强化/再巩固、衰减归档、语义续页。不要把以前讨论的Fragment、Saga、多张Self/Belief数据库当成已实现组件。首版也不需要为了名词齐全重建这些模块。[H04][H06][H10][H13]

Herta代码MIT许可不自动覆盖角色prompts、图像、游戏对白、声音。可以借机制、在许可范围移植源码并保留署名，但不能批量换角色名字当原创。正式角色/模型/音色另需合法来源与再分发授权。[H16]

## 3. 总体架构与默认实现路线

```text
用户 / 固定遐蝶界面
        │
 Xiadie应用协调层
   ┌────┴──────────────────┐
   │                       │
Core/Life服务          ZCode主Runtime
身份、记忆、             会话、项目Memory、
上下文、Dream政策        工具、工作与子代理
   │                       │
   └──有界Context───────────┤
                           ├──原生工具 / MCP / Skills
                           └──DSH Bridge
                                  │
                             DSH工作包/团队
                                  │
                             插件与内部子代理
```

默认先验证“ZCode主模型读Xiadie上下文、进行工作、形成最终回复”的低开销路线。Core不是每轮额外跑一次的大模型，逻辑上身份数据独立也不要求物理上每句话都双模型处理。不要先做人格二次改写来掩盖运行时无法保持角色的问题。

若公开Hook和服务无法满足身份/证据/独立桌面要求，P00/P01用PoC比较薄呈现适配、小范围下游patch和独立Self Runtime。后者需说明额外调用、权限、事件和恢复成本，经ADR才采用。**不以“上面再加一层”掩盖无法验证的接缝。** 无论选哪条，Core都不直接选择DSH插件。[Z02][Z10][H02]

### 3.1 所有权

| 对象 | 主权威 / 写入者 | 备注 |
|---|---|---|
| 固定人格 | 原创版本化Markdown与manifest | 模型不能自动改 |
| Runtime原始轨迹 | 对应Runtime原生记录 | Xiadie只保必要证据投影与来源 |
| 规范化事实 | Xiadie事件store | 带origin，不能和原始日志互相重写 |
| Life/CoreAnchor/语义页 | 一个Life store，受控提交服务 | Markdown是导出视图，不是第二个自由写入源 |
| 项目正式知识 | 原生Memory和已合并代码/文档/ADR | 按新事实修订，不按时间遗忘 |
| 子代理笔记 | 对应profile的局部scope | 不是正式项目结论，不默认可信 |
| 工程任务状态 | 一个选定的协调账本 | Owner/lease/head/review必须一致 |
| 个人待办 | 个人任务store | 与工程工作包只关联不复制状态 |
| 文件知识 | 明确授权导入域 | 源/索引/版本/删除互相可追 |

### 3.2 接口，不是假定存在的上游API

`ContextPacket`带身份片段、Life快照、来源类型、预算与版本；`RuntimeEvent`带turn/run/attempt/sequence与真实状态；`WorkPackage`带目标、project、允许路径/工具/网络、预算和验收；`ResultPackage`带base/head、产物hash、测试及unknown effects；`DreamProposal`带source_refs、base_version、privacy_epoch与验证结果。

这些是**Xiadie目标契约**。例如本地MCP提供cancel_work_package不代表DSH有session/cancel；adapter必须写清真实映射和不支持项。Mock检查本地格式，真实进程试验证明上游互通，两者都需要。

## 4. 代码复用与差额开发

### 4.1 五种采用方式

直接依赖成熟接口最优；接口差一点则写薄adapter；需要复制时优先提取纯逻辑和对应测试并保留版权；语义绑定角色或存储时借结构重新实现；前面都不合适才开发最小缺口。每个自研决定必须带已查方案、真实不匹配证据和仍值得借鉴的内容。

| 来源 | 直接用 / 可移植候选 | 改造或借思想 | 不拿 |
|---|---|---|---|
| ZCode | 原生Loop、tools、MCP、project memory、可用服务/UI | Hook上下文、项目迁移、事件投影 | 重新写完整框架；未知账号/遥测配置 |
| DSH | 官方SDK、已有插件、独立进程 | 工作包、权限、结果证据、进程取消 | 源码级硬融合、虚构细粒度协议 |
| Herta | 合规纯函数、分段和检查代码及测试 | 再巩固、有限前缀、语义化、调度 | 专属角色语料、完整coprocessor |
| dsh-comfyui-ctl | client/safety/mock与插件 | 实例所有权与工作包适配 | 顺手重写客户端和未发布多实例 |
| Cyrene | 无运行依赖 | 角色状态、气泡、工作呈现 | 整体fork和视觉资产直接搬运 |
| 本地队列/协调工具 | PoC通过者 | lease、checkpoint、消息、工作树 | 多套竞争账本、未审查安装脚本 |

详细到文件、固定链接、用途、禁止项的清单在《代码参考与复用清单》。DelayKit、lite-q、MCP Agent Mail、Rhizome、Solo仅是先前发现的候选，尚未在Xiadie中通过PoC。不要将候选列表当依赖批准书。[Q01][Q02][Q03][Q04][Q05]

### 4.2 先找再试的阶段门槛

每阶段先形成搜索与源码比较，再在隔离数据根运行最小试验；阶段采用决定生效后，才允许生产实现。研究任务不要求“本阶段已存在采用决定”，因为决定正是调查与试验的输出，不能形成语义上的前置循环。

试验至少覆盖成功、失败和恢复。缺少Key时可以mock，但真实互通必须标NOT_RUN。候选安装前先读脚本，禁止静默替换全局CLI、改用户配置或清数据。采用外部组件后，只做缺少的策略，不继续保留同职责竞品来互相同步。

## 5. Memory与Dream的详细政策

### 5.1 Life不是项目备忘录

固定人格稳定；少量用户确认的核心锚点不自然衰减但能删除；普通生活经历可强化、再解释和归档；有界语义页保存由真实经历形成的互动认识；档案保存可按需查询的历史证据。角色虚构示例必须另域，不能“回忆”成用户一起经历过的事。

Project Memory保存非显然工程经验、已验证约束、参考指针。代码结构、测试命令等已在仓库清楚记录的东西，不需要重复记一遍。实时进度和Owner由task账本管理，Memory只指向它。项目多年未开需要核对新鲜度，不应因此被遗忘。

Herta90天半衰期只用于对照：不是90天后删除，也不是保证能活8个月。容量竞争会提前归档；被重复使用可能增强显著性，但自我复述不证明真实。语义页也不是永恒真理，必须允许明确纠正。[H03][H09][H17]

### 5.2 一条记忆怎样进入长期状态

```text
已提交来源
 → 稳定Episode分段（代码）
 → 必要证据摘要（优先代码）
 → worthiness候选（受限模型）
 → 同事件/独立证据检查
 → 叙述或再巩固候选
 → 引语/来源/否定/未完成状态/事实性/格式验证
 → 版本、epoch、租约检查
 → 事务提交、生成只读导出视图
```

失败、取消和用户纠正也可能是重要来源；但未提交的流式草稿不能冒充已经说完的话。用户说X与X是外部真相是两件事。助手建议不能因被总结就变成用户决定。来源引用必须回到原始证据，而非总结的总结。

后台模型没有任意Shell、安装、外发和写数据库权限。结构化输出允许空结果/abstain；缺来源、缺必需评分、坏ID就拒绝。漂亮文笔不能抵消假事实。评审模型分数只是信号，不能充当真值。

### 5.3 Dream并不等于另一个常驻大Agent

分段、去重、预算、权限、原话匹配、提交、恢复都是确定性代码。模型只承担局部语义判断和候选生成。可以一个模型多阶段，也可以便宜模型筛选再强模型生成；以质量和费用对照试验决定，不默认多模型一定更可靠。

Dream先手动运行，后续用 **Shadow→Advisory→Active** 逐级开放自动提交：Shadow只记录候选和差异；Advisory让用户检查；Active仅在通过固定评测、明确授权和可回滚域中提交。身份级核心锚点不随Active放开自动改写。该晋级规则是Xiadie政策，不声称Herta已经按同名方式实现。

### 5.4 机会式调度与关闭应用

触发分“需要整理”和“现在允许”。前者看未处理材料、待fold、明确纠正、冲突与积压；后者看前台工作、审批、录音、GPU任务、预算和用户开关。关闭15天没有新材料，不等于欠15次Dream。

启动先本地查积压，UI立即可用。有短空闲就处理一小批，用户回来后不再发新的后台模型调用，在安全阶段边界让路。一直没有空闲时显示积压和手动入口，不强迫程序常驻。托盘驻留和完全退出分别设置；完全退出终止owned调度/进程，不能声称离线期间一直想用户。

持久作业记录stage、输入hash、prompt/model版本、输出ref、lease_generation、epoch和重试时间。已验证步骤可复用；未知云端调用可能已经计费，不能宣称恢复不重复计费。at-least-once尝试靠幂等提交减重复，不保证外部副作用恰好一次。

### 5.5 初始参数属于待试假设

建议首轮将CoreAnchor控制在8条/800tokens内、live shelf从16条/2400tokens起测，语义页约600–1000中文字符但按tokenizer复算。后台并发1、每批1–3Episode，启动catchup空闲2–5分钟可作为实验组。Herta默认值另做对照。不是测量结论，模型上下文更小时须减预算或明确不支持该配置。

## 6. 每轮Prompt怎样取舍

角色资产与受信任应用规则在指令域；CoreAnchor、语义页和有限shelf是有来源状态；项目规则/知识由原生工作层按当前项目提供；归档和外部文档只在问题需要时读取。不同域不能互相复制后变成多个权威。

最高优先级是固定边界、当前用户输入、必要审批和执行证据；其次是相关项目上下文与有界Life。工具schema也占窗口。预算不足先去重复、压缩风格例子和不相关历史，不能偷偷截掉当前用户请求后继续装作理解完整。

问原话优先回源；问当前进度优先工程事实；问共同经历才用Life；问当下看法区分意见和依据。每轮固定context_version，后台Dream不在同一轮半途重写已发送前缀。MCP resource存在不代表自动注入，具体Hook生效时机必须实测。[H13][H14][Z02][Z10]

## 7. 大型项目协作与执行安全

ZCode业务主Agent拆任务；确定性协调服务保证原子Owner和状态。DSH接WorkPackage可自己拆子任务，但根预算和scope只可收紧。初版禁止DSH又反向委托ZCode，避免无限循环。

每个独立代码写者一个worktree。DSH组内若共享目录，只能一人写、其他只读；只读profile还须防原生memory自动加写工具。二进制资产用独占副本，不做文本merge。lease过期只撤提交权，不证明旧进程已停止；重派写任务前须处理旧执行者隔离。

消息只传任务、状态、问题、检查点、结果，带ID、版本、ack，不建无界Agent聊天群。最终包带base/head、文件hash、测试和未知效果；review绑定精确head，改后重审。唯一集成者merge再跑受影响测试，之后才更新正式项目知识。

Git工作树、文件预约、工具隐藏都不是OS沙箱。任意Shell/Node插件可能访问其他路径。执行端的权限限制、可信插件范围及不能保证的边界必须写明；未能限制的能力不宣传为安全可用。[T02][T03][Q03][Z04]

## 8. 隐私、导出、备份与删除

数据可见、可编辑、可禁用注入、可导出、可删除。删除时先增加privacy_epoch，再让source→episode→语义页→索引/cache/job传播失效，旧候选提交必须拒绝。日志与诊断默认不含Key、私密正文和供应商隐藏推理。

备份使用一致性接口，记录schema/hash和包含原文范围；不能把活跃db主文件随便拷走就算备份。恢复先在新根验证，再对账本机较新删除墓碑，旧backup不能静默复活删除信息或执行旧副作用待办。[T05]

无法替用户抹除他自行复制的外部文件、旧离线备份或供应商服务器保留内容，必须说明范围。模型Key通过系统凭据/安全存储或明确开发配置加载，不进入Prompt和证据包。[T04]

## 11. 测试、成本和版本决策

纯函数测边界与确定性；存储测事务/幂等/强杀/备份；Runtime测真实通知与错误；Memory有人工gold，重点建议≠决定、原话、否定、纠正和未完成；协作测双claim/旧lease/共享接口/review版本；隐私测删除复活和跨scope泄露；桌面测DPI/托盘/退出/无Key；发行测实际安装包而非仅开发目录。

固定关键负例必须无已知未关闭失败，但不要宣传“永远不会错记”或“完全防住注入”。模型评分不是客观概率。每次实验保存代码/model/prompt/config/样本hash、环境、命令、输出、actual/estimated token与费用来源。

版本无固定工期承诺。先根据PoC和可执行单元统计实际完成量，再滚动排期。资源等待与技术失败分开记录。不要为了凑进度把blocked删除或改名成optional。

## 12. 风险及发布阻断

| 风险 | 阶段 | 必须处理 |
|---|---|---|
| 主接缝不能稳定注入角色或采证 | P00–P01 | 真PoC后决定adapter/小patch/独立Self，不先造多层 |
| DSH缺远程cancel/approval | P00/P07 | 专属进程与受限包，不默认approve |
| 子代理memory自动增加写工具 | P00/P03/P08/P09 | 核最终工具集、执行端路径/动作；只读profile不能只靠Prompt |
| 项目或Life互相污染 | P03/P04/P09 | scope、唯一权威、最小handoff和删除传播 |
| Dream错记并强化 | P04–P06 | 来源、原话、缺评分拒绝、关闭自回声可信度增强 |
| 短会话永远无Dream机会 | P06 | backlog可见、小批catchup、手动入口，不强制常驻 |
| 强杀重试重复外部效果 | P02/P07/P13 | operation_id/receipt，unknown先查 |
| lease过期但老worker仍写 | P08 | fence提交＋实际执行隔离，再移交 |
| 删除被旧job/备份复活 | P09/P14 | epoch/派生图/墓碑/恢复对账 |
| 资源授权缺失 | P00/P10/P12/P15 | 缺证据不发行，开发placeholder不替代最终角色 |
| 上游breaking change | 全程 | 锁版本，单独升级分支，先查试再回归 |
| UI扩张成工作台且角色入口丢失 | P10 | 旧终局要求核对；一个主窗口，低频面板化 |

## 13. 1.0完成定义与交接

所有冻结Must需有真实验收；关键事实/权限/数据失败已关闭；角色、模型、声音和代码来源明确；下载的实际包与测试hash一致；用户可以正常聊天、续做旧项目、管理Life、停止Dream、查看工作证据、使用已承诺文件/任务/语音/渠道能力；导出删除、备份恢复、升级回退与完全退出均演练。

已写好计划卡不算完成一个软件单元，mock通过不算真实互通，源码可读不算授权素材，模型说成功不算测试成功。交付的是可复核证据而非完工叙述。1.0.x维护只修安全/兼容/质量，新能力另立计划。

## 14. 本次重建修订的明确化事项

本包保留17阶段、183单元的规模与0.0.0至1.0.0路线；不是对无法挂载的旧二进制包进行逐字比较。主要明确化：研究任务不要求尚未生成的采用决定；阶段集成明确依赖所有实现单元；子代理只读权限检查加入memory自动增写工具负例；关键source状态区分本轮复读与前序材料；Shadow/Advisory/Active逐步启用自动记忆；任务卡只附需要的来源，减少重复上下文。

实施者应使用本包文档1.1和对应tasks.json作为一致版本，不混用旧编号文字、旧sources与新任务卡。全部任务当前仍为not_started。
